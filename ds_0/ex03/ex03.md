# Ex03 - Automatic table

## 1. Alistirmanin amaci

Ex03 senden `subject/customer` klasorundeki **butun CSV dosyalarini otomatik olarak** PostgreSQL veritabanina aktarmanı ister.

Her CSV dosyasi icin:

- CSV basligindaki sutunlarla bir PostgreSQL tablosu olusturulmali.
- Tablo adi, dosya adinin `.csv` uzantisi cikarilmis hali olmali.
- CSV'deki kayitlar tabloya yuklenmeli.

Mevcut dosyalar sunlardir:

```text
subject/customer/data_2022_dec.csv
subject/customer/data_2022_nov.csv
subject/customer/data_2022_oct.csv
subject/customer/data_2023_jan.csv
```

Buna gore beklenen tablolar:

```text
data_2022_dec
data_2022_nov
data_2022_oct
data_2023_jan
```

Ex03 icin teslim edilmesi gereken dosya adi `automatic_table.*` olmalidir. Ornegin:

```text
ex03/automatic_table.sh
```

---

## 2. Ex02 ile farki

Ex02'de tek bir CSV dosyasini elle tanimlamistin:

```sql
CREATE TABLE data_2022_oct (...);
\copy data_2022_oct FROM '../subject/customer/data_2022_oct.csv' ...;
```

Bu yontemde dosya adi, tablo adi ve sutunlar sabittir. Ex03'te ayni islemi dort dosya icin tek tek kopyalamak yerine script:

1. `customer` klasorundeki `.csv` dosyalarini bulur.
2. Her dosyanin adindan tablo adini uretir.
3. Tabloyu olusturur.
4. Ilgili CSV verisini tabloya aktarir.

Boylece yeni bir CSV dosyasi klasore eklendiginde script onu da otomatik olarak isleyebilir.

## 3. Onerilen cozum: shell script

`ex03/automatic_table.sh` dosyasini olustur ve su icerigi kullan:

```bash
#!/usr/bin/env bash

set -euo pipefail

SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_DIR="$(cd -- "$SCRIPT_DIR/.." && pwd)"
CUSTOMER_DIR="$PROJECT_DIR/subject/customer"

DB_HOST="${PGHOST:-localhost}"
DB_PORT="${PGPORT:-5432}"
DB_USER="${PGUSER:-acosgun}"
DB_NAME="${PGDATABASE:-piscineds}"

for csv_file in "$CUSTOMER_DIR"/*.csv; do
    [ -e "$csv_file" ] || continue

    table_name="$(basename "$csv_file" .csv)"

    psql -h "$DB_HOST" -p "$DB_PORT" -U "$DB_USER" -d "$DB_NAME" \
        -v ON_ERROR_STOP=1 \
        -v table_name="$table_name" \
        -v csv_file="$csv_file" <<'SQL'
DROP TABLE IF EXISTS :"table_name";

CREATE TABLE :"table_name" (
    event_time TIMESTAMPTZ,
    event_type VARCHAR(32),
    product_id INTEGER,
    price NUMERIC(10, 2),
    user_id BIGINT,
    user_session UUID
);

\copy :"table_name" FROM :'csv_file' WITH (FORMAT csv, HEADER true)
SQL

done
```

> Not: `DB_USER` degerini kendi okul login'in ile degistir. Bu repository'deki Docker ayarinda kullanici `acosgun` olarak tanimlidir. Farkli bir login kullaniyorsan hem `ex00/docker-compose.yml` hem de script ayni kullaniciyi gostermelidir.

## 4. Scriptin bolumleri ne yapiyor?

### Shebang

```bash
#!/usr/bin/env bash
```

Dosyanin Bash ile calistirilmasini saglar.

### Hata kontrolu

```bash
set -euo pipefail
```

- `-e`: Bir komut hata verirse script durur.
- `-u`: Tanimlanmamis degisken kullanilmasini hata sayar.
- `pipefail`: Bir pipe zincirindeki komutlardan biri hata verirse bunu gizlemez.

Bu, scriptin sessizce yarim kalmasini engeller.

### Proje yolunu bulma

```bash
SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_DIR="$(cd -- "$SCRIPT_DIR/.." && pwd)"
CUSTOMER_DIR="$PROJECT_DIR/subject/customer"
```

Script hangi klasorden calistirilirsa calistirilsin, CSV klasorunu scriptin konumuna gore bulur. Bu nedenle sadece `ex03` klasorunden calistirma zorunlulugu azalir.

### PostgreSQL baglanti bilgileri

```bash
DB_HOST="${PGHOST:-localhost}"
DB_PORT="${PGPORT:-5432}"
DB_USER="${PGUSER:-acosgun}"
DB_NAME="${PGDATABASE:-piscineds}"
```

Varsayilanlar senin Docker ayarinla uyumludur:

- host: `localhost`
- port: `5432`
- kullanici: `acosgun`
- veritabani: `piscineds`

Ortam degiskenleri verilirse varsayilanlarin yerine onlar kullanilir. Ornegin:

```bash
PGUSER=ogrenci psql ...
```

Ancak scripti ilk kullanirken sabit degerlerle baslamak daha kolaydir.

### CSV dosyalarini otomatik bulma

```bash
for csv_file in "$CUSTOMER_DIR"/*.csv; do
```

Bu dongu `customer` klasorundeki her `.csv` dosyasi icin bir kez calisir.

```bash
[ -e "$csv_file" ] || continue
```

Klasorde hic CSV yoksa Bash'in olusturabilecegi sahte `*.csv` degerini atlar.

### Tablo adini dosya adindan uretme

```bash
table_name="$(basename "$csv_file" .csv)"
```

Ornegin:

```text
/home/.../data_2022_oct.csv
```

degerinden:

```text
data_2022_oct
```

uretilir. Boylece dosya adini ve tablo adini dort kez elle yazmak gerekmez.

### `psql` secenekleri

```bash
psql -h "$DB_HOST" -p "$DB_PORT" -U "$DB_USER" -d "$DB_NAME" \\
    -v ON_ERROR_STOP=1 \\
```

- `-h localhost`: Docker konteynerine aktarilan TCP portu kullanir.
- `-p 5432`: PostgreSQL portudur.
- `-U`: PostgreSQL kullanicisidir.
- `-d`: Veritabani adidir.
- `-v ON_ERROR_STOP=1`: SQL hatasinda devam etmek yerine scripti durdurur.

`-h localhost` ozellikle onemlidir. Bunu yazmazsan `psql`, yerel Unix socket arayabilir ve Docker PostgreSQL calisiyor olsa bile baglanti hatasi verebilir.

### SQL'i Bash icinden calistirma

```bash
psql ... <<'SQL'
...
SQL
```

Bu yapinin adi heredoc'tur. Aradaki SQL metni `psql` komutuna aktarilir. Her CSV icin tablo adi ve dosya yolu `-v` ile SQL tarafina gonderilir:

```bash
-v table_name="$table_name"
-v csv_file="$csv_file"
```

SQL icinde:

```sql
DROP TABLE IF EXISTS :"table_name";
```

tablo varsa siler. Bu sayede script tekrar calistirilabilir.

```sql
CREATE TABLE :"table_name" (
    event_time TIMESTAMPTZ,
    event_type VARCHAR(32),
    product_id INTEGER,
    price NUMERIC(10, 2),
    user_id BIGINT,
    user_session UUID
);
```

CSV basligi her dosyada ayni oldugu icin Ex02'deki uygun PostgreSQL tipleri burada da kullanilir.

```sql
\copy :"table_name" FROM :'csv_file' WITH (FORMAT csv, HEADER true)
```

- `\copy`: CSV verisini istemci tarafindan PostgreSQL tablosuna aktarir.
- `HEADER true`: Ilk satirin sutun basligi oldugunu ve veri olarak aktarilmamasi gerektigini belirtir.
- `FORMAT csv`: Dosyanin CSV formatinda oldugunu belirtir.

`\copy` kullanilmasinin avantaji, CSV dosyasinin senin bilgisayarinda bulunmasidir. `COPY` kullanirsan dosyanin PostgreSQL konteyneri icinden gorunur olmasi gerekebilir.

## 5. Dosyayi calistirma

Ilk olarak scripti calistirilabilir yap:

```bash
chmod +x ex03/automatic_table.sh
```

Docker PostgreSQL'i baslat:

```bash
cd ex00
docker compose up -d
```

Sonra proje kokune don ve scripti calistir:

```bash
cd ..
PGPASSWORD=mysecretpassword ./ex03/automatic_table.sh
```

`PGPASSWORD` sadece bu komut icin sifreyi verir. Daha guvenli ve parola sormasini isteyen alternatif:

```bash
./ex03/automatic_table.sh
```

Bu komut calisirken `psql` senden PostgreSQL sifresini isteyebilir. Sifre:

```text
mysecretpassword
```

## 6. Sonucu kontrol etme

Dort tablonun olustugunu kontrol et:

```bash
PGPASSWORD=mysecretpassword psql \
    -h localhost \
    -U acosgun \
    -d piscineds \
    -c '\dt'
```

Tablolardan birinin satir sayisini kontrol et:

```bash
PGPASSWORD=mysecretpassword psql \
    -h localhost \
    -U acosgun \
    -d piscineds \
    -c 'SELECT COUNT(*) FROM data_2022_oct;'
```

Ilk kayitlari gor:

```bash
PGPASSWORD=mysecretpassword psql \
    -h localhost \
    -U acosgun \
    -d piscineds \
    -c 'SELECT * FROM data_2022_oct LIMIT 5;'
```

Kolon tiplerini kontrol et:

```bash
PGPASSWORD=mysecretpassword psql \
    -h localhost \
    -U acosgun \
    -d piscineds \
    -c '\d data_2022_oct'
```

Beklenen tablo listesi:

```text
 data_2022_dec
 data_2022_nov
 data_2022_oct
 data_2023_jan
```

CSV'deki basliklar ile PostgreSQL tablosundaki kolon adlari ayni olmalidir:

```text
event_time
 event_type
 product_id
 price
 user_id
 user_session
```

## 7. Sik yapilan hatalar

### PostgreSQL sunucusu bulunamiyor

Su hatayi gorursen:

```text
connection to server ... failed: No such file or directory
```

Docker konteyneri calismiyor olabilir. Kontrol et:

```bash
docker compose -f ex00/docker-compose.yml ps
```

Baslat:

```bash
docker compose -f ex00/docker-compose.yml up -d
```

### Kimlik dogrulama hatasi

```text
password authentication failed
```

Kullanici adinin ve sifrenin `ex00/docker-compose.yml` ile ayni oldugunu kontrol et:

```text
kullanici: acosgun
veritabani: piscineds
sifre: mysecretpassword
```

### `relation already exists`

Scriptte `DROP TABLE IF EXISTS` oldugu icin normal calistirmada bu hata beklenmez. Elle yazilan baska bir SQL dosyasi tabloyu zaten olusturduysa scriptin tabloyu silip yeniden olusturmasi beklenir.

### CSV dosyasi bulunamiyor

Scriptteki yol su klasoru gostermelidir:

```text
project-root/subject/customer
```

`automatic_table.sh` dosyasinin yeri:

```text
project-root/ex03/automatic_table.sh
```

### `permission denied`

Script calistirilabilir degilse:

```bash
chmod +x ex03/automatic_table.sh
```

komutunu calistir veya dogrudan su sekilde baslat:

```bash
bash ex03/automatic_table.sh
```
