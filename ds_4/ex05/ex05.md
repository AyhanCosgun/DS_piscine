# 1. KNN nedir?

**KNN = K-Nearest Neighbors = K En Yakın Komşu.**

Temel fikir son derece basittir:

> Yeni gelen bir örneğin sınıfını, eğitim verisindeki kendisine en yakın
> `k` örneğin sınıflarına bakarak belirle.

Örneğin elimizde iki boyutlu bir feature uzayı olsun:

``` text
feature_2
   │
   │        S       S
   │
   │             ?
   │
   │     J    J
   │  J
   └──────────────────── feature_1
```

`?` yeni knight olsun.

`k = 3` seçelim.

Yeni noktanın en yakın üç komşusu:

``` text
1. komşu → Jedi
2. komşu → Jedi
3. komşu → Sith
```

Oylama:

``` text
Jedi = 2
Sith = 1
```

Sonuç:

``` text
Jedi
```

KNN'in en önemli özelliği şudur:

> KNN klasik anlamda `fit()` sırasında bir karar ağacı gibi bölme kurmaz
> veya Random Forest gibi yüzlerce tree öğrenmez.

KNN esas olarak training örneklerini saklar ve prediction sırasında yeni
noktanın komşularını arar.

Bu nedenle KNN çoğu zaman **instance-based** veya **lazy learning**
yaklaşımı olarak anlatılır.

# 2. Soru 1 --- KNN'nin DS2'deki K-Means Clustering ile direkt veya dolaylı bir alakası var mı?

**Soru:** Öncelikle bu KNN'nin daha önce DS2 projesinde yaptığımız
K-Means Clustering algoritması ile direkt veya dolaylı bir alakası var
mı? KNN biraz ona benziyor.

## Kısa cevap

**Doğrudan aynı algoritma değiller.**

Ama ikisinin de ortak matematiksel fikri vardır:

> Feature uzayındaki noktalar arasındaki **uzaklık** kavramını
> kullanabilirler.

Bu yüzden KNN sana K-Means'i hatırlatıyor ve bu benzerlik tamamen
mantıklı.

------------------------------------------------------------------------

## K-Means ne yapıyordu?

DS2'de K-Means:

``` text
Nokta
  │
  ▼
en yakın centroid'i bul
  │
  ▼
cluster'a ata
  │
  ▼
centroid'leri yeniden hesapla
  │
  ▼
tekrar et
```

Örneğin:

``` text
             ● ● ●
           ●   C1

                         ● ●
                       ● C2
```

Buradaki `C1` ve `C2` centroid'lerdir.

K-Means:

> "Bu nokta hangi cluster'ın merkezine daha yakın?"

diye düşünür.

------------------------------------------------------------------------

## KNN ne yapıyor?

KNN'de ise centroid yoktur.

``` text
Training points
      │
      ▼
Yeni nokta
      │
      ▼
En yakın k training noktası
      │
      ▼
Komşuların sınıflarını oylama
      │
      ▼
Jedi / Sith
```

Yani:

``` text
K-Means
────────────
En yakın CENTROID
       │
       ▼
   CLUSTER

KNN
────────────
En yakın TRAINING POINTS
       │
       ▼
    CLASS
```

------------------------------------------------------------------------

## En önemli fark

K-Means **unsupervised learning** algoritmasıdır.

Elinde:

``` text
X
```

vardır ama:

``` text
y
```

yoktur.

Örneğin:

``` text
● ● ● ●
○ ○ ○ ○
```

noktalarını kendisi gruplandırmaya çalışır.

KNN ise **supervised learning** algoritmasıdır.

Elinde:

``` text
X + y
```

vardır.

Örneğin:

``` text
● = Jedi
○ = Sith
```

Yeni noktanın hangi sınıfa ait olduğunu öğrenmeye çalışır.

------------------------------------------------------------------------

## Çok güzel bir zihinsel bağlantı

``` text
K-Means
"En yakın merkezin hangi cluster'ı?"

KNN
"En yakın noktaların hangi sınıfı?"
```

Dolayısıyla:

> **KNN ile K-Means aynı şey değildir; fakat ikisi de feature uzayındaki
> uzaklık fikrinden yararlanır.**

Bu yüzden KNN sana K-Means'i hatırlatması doğru bir sezgidir.

# 3. Soru 2 --- KNN'deki yakınlık tam olarak nedir?

**Soru:** Buradaki "yakınlık", feature'ların sayısal değerlerinden elde
edilen, scale edilmiş `R^n` tuple noktalarının birbirine olan Euclidean
uzaklığı değil mi?

**Evet.**

Senin bu dataset için düşündüğün matematiksel model tam olarak budur.

Bir knight'ın 30 feature'ı olduğunu düşünelim.

Bir örnek:

``` text
x = (x₁, x₂, x₃, ..., x₃₀)
```

başka bir örnek:

``` text
z = (z₁, z₂, z₃, ..., z₃₀)
```

olarak düşünülebilir.

Bunlar:

``` text
R³⁰
```

içinde iki nokta gibi düşünülebilir.

------------------------------------------------------------------------

## Euclidean distance

İki nokta arasındaki klasik Euclidean uzaklık:

\[ d(x,z) = `\sqrt{
(x_1-z_1)^2+
(x_2-z_2)^2+
\cdots+
(x_{30}-z_{30})^2
}`{=tex} \]

Genel olarak `n` feature için:

\[ d(x,z) = `\sqrt{
\sum_{i=1}^{n}
(x_i-z_i)^2
}`{=tex} \]

KNN'nin temel fikri:

``` text
distance küçük
      │
      ▼
noktalar birbirine yakın
      │
      ▼
komşu olma ihtimali yüksek
```

# 4. Peki neden scaling çok önemli?

KNN uzaklık kullandığı için feature ölçekleri çok önemlidir.

Örneğin iki feature olsun:

``` text
Strength:     0 - 1000
Sensitivity:  0 - 1
```

İki nokta arasında:

``` text
Strength farkı     = 300
Sensitivity farkı  = 0.2
```

olsun.

Euclidean uzaklık:

\[ d = `\sqrt{
300^2 + 0.2^2
}`{=tex} \]

olur.

Burada neredeyse bütün uzaklığı `Strength` belirler.

Dolayısıyla model:

> "Sensitivity önemli değil."

demese bile matematiksel olarak `Strength` uzaklığa çok daha fazla
katkıda bulunur.

# 5. StandardScaler neden Ex05'te özellikle mantıklı?

Senin kodunda:

``` python
Pipeline([
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(n_neighbors=k))
])
```

kullanıyorsun.

`StandardScaler`, her feature'ı yaklaşık olarak:

\[ z = `\frac{x-\mu}{\sigma}`{=tex} \]

dönüşümüyle standardize eder.

Böylece feature'lar karşılaştırılabilir bir ölçeğe gelir.

Örneğin:

``` text
Feature A
ortalama = 100
std      = 20

Feature B
ortalama = 0.5
std      = 0.1
```

olsa bile scaling sonrası ikisinin de yaklaşık:

``` text
ortalama ≈ 0
std      ≈ 1
```

ölçeğinde olması sağlanır.

------------------------------------------------------------------------

# 6. Pipeline kullanman neden doğru?

Senin kodun:

``` python
model = Pipeline([
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(n_neighbors=k))
])
```

şeklinde.

Bu çok iyi bir tercih.

Çünkü:

``` text
X_train
   │
   ▼
StandardScaler.fit_transform()
   │
   ▼
scaled X_train
   │
   ▼
KNN.fit()
```

ve validation aşamasında:

``` text
X_validation
   │
   ▼
aynı scaler.transform()
   │
   ▼
scaled X_validation
   │
   ▼
KNN.predict()
```

akışını otomatik yönetir.

Önemli nokta:

> Validation verisinin ortalaması ve standart sapması ayrı ayrı
> öğrenilmemelidir.

Scaler yalnızca training verisinden öğrenmelidir.

Pipeline bunu doğru şekilde yapar.

# 14. Peki grafikte neden "accuracy" yazıyor olabilir?

Burada önemli bir terminoloji problemi var.

**Accuracy, precision ile aynı şey değildir.**

Accuracy:

\[ Accuracy = `\frac{TP+TN}`{=tex} {TP+TN+FP+FN} \]

Precision:

\[ Precision = `\frac{TP}`{=tex} {TP+FP} \]

Recall:

\[ Recall = `\frac{TP}`{=tex} {TP+FN} \]

F1:

\[ F1 = `\frac{2PR}`{=tex} {P+R} \]

Dolayısıyla:

``` text
accuracy ≠ precision
```

# 18. Soru 4 --- Precision hangi sınıfa göre hesaplanıyor?

**Soru:** Precision hesaplarken iki sınıftan birine rastgele "positive"
mi diyeceğiz?

Burada `precision_score()`'un `average` parametresi devreye giriyor.

İki sınıfımız:

``` text
Jedi
Sith
```

olsun.

Eğer:

``` python
average="binary"
```

kullanırsan bir tane **positive class** seçmen gerekir.

Örneğin:

``` python
precision_score(
    y_true,
    y_pred,
    pos_label="Jedi",
    average="binary",
)
```

dediğinde:

``` text
Positive = Jedi
Negative = Sith
```

olur.

Bu durumda precision:

\[ Precision\_{Jedi} = `\frac{TP_{Jedi}}`{=tex} {TP\_{Jedi}+FP\_{Jedi}}
\]

olarak hesaplanır.

------------------------------------------------------------------------

# 19. Positive class gerçekten rastgele mi?

Hayır.

"Positive" kelimesinin burada:

> "iyi sınıf"

gibi bir anlamı yoktur.

Binary classification'da sınıflardan biri metrik hesabı için pozitif
sınıf olarak seçilir.

Örneğin:

``` text
Positive = Jedi
Negative = Sith
```

veya tam tersi olabilir.

Bu seçimin anlamlı bir şekilde yapılması gerekir.

Ama **weighted/macro averaging** kullanırsan tek bir positive class
seçmek zorunda kalmazsın.

------------------------------------------------------------------------

# 20. `average="weighted"` ne yapıyor?

Senin kodunda:

``` python
precision_score(
    y_validation,
    validation_pred,
    average="weighted"
)
```

var.

Bu durumda sklearn:

1.  Jedi precision'ını hesaplar.
2.  Sith precision'ını hesaplar.
3.  Her sınıfın sample sayısını dikkate alır.
4.  Support'a göre ağırlıklı ortalama alır.

Örneğin:

``` text
Jedi precision = 0.90
Jedi support   = 60

Sith precision = 0.80
Sith support   = 20
```

olsun.

Weighted precision:

\[ P\_{weighted} = `\frac{
60(0.90)+20(0.80)
}`{=tex} {60+20} \]

olur.

Yani:

``` text
çok sample'a sahip sınıf
        │
        ▼
daha fazla ağırlık
```

alır.

------------------------------------------------------------------------

# 21. Macro ve weighted farkı

İki sınıf için:

``` text
Jedi precision = 0.90
Sith precision = 0.80
```

olsun.

Macro:

\[ P\_{macro} = `\frac{0.90+0.80}{2}`{=tex} \]

Weighted ise support'ları da dikkate alır.

Dolayısıyla:

``` text
macro
   │
   └──► bütün sınıflara eşit ağırlık

weighted
   │
   └──► sample sayısı fazla olan sınıfa daha fazla ağırlık
```

Bu ayrım özellikle class imbalance olduğunda önemlidir.

------------------------------------------------------------------------

# 22. `precision_score()` tüm önemli parametreleri

Scikit-learn'in binary/multiclass precision metriği için temel imza:

``` python
precision_score(
    y_true,
    y_pred,
    *,
    labels=None,
    pos_label=1,
    average="binary",
    sample_weight=None,
    zero_division="warn",
)
```

Aşağıda her parametreyi ayrı ayrı inceleyelim.

------------------------------------------------------------------------

## `y_true`

Gerçek etiketlerdir.

Örneğin:

``` python
y_true = [
    "Jedi",
    "Sith",
    "Jedi",
    "Sith",
]
```

------------------------------------------------------------------------

## `y_pred`

Modelin tahminleridir.

Örneğin:

``` python
y_pred = [
    "Jedi",
    "Jedi",
    "Jedi",
    "Sith",
]
```

------------------------------------------------------------------------

## `labels=None`

Hangi sınıfların metrik hesabına dahil edileceğini belirler.

Varsayılan:

``` python
labels=None
```

ise sınıflar otomatik olarak belirlenir.

Örneğin:

``` python
labels=["Jedi", "Sith"]
```

ile açıkça sınıf sırasını/dahil edilen sınıfları belirleyebilirsin.

------------------------------------------------------------------------

## `pos_label=1`

Binary durumda positive class'ı belirtir.

Varsayılan:

``` python
pos_label=1
```

dir.

Örneğin:

``` python
pos_label="Jedi"
```

diyebilirsin.

Ancak:

``` python
average="binary"
```

kullanırken anlamlıdır.

`average="weighted"` kullandığında tek bir positive class seçme mantığı
kullanılmaz.

------------------------------------------------------------------------

## `average="binary"`

Varsayılan değerdir.

Binary classification'da yalnızca positive class için precision
hesaplar.

Örneğin:

``` python
average="binary"
pos_label="Jedi"
```

ise yalnızca Jedi precision'ı raporlanır.

Diğer seçenekler:

``` text
None
"binary"
"micro"
"macro"
"weighted"
"samples"
```

------------------------------------------------------------------------

## `average=None`

Her sınıf için ayrı precision döndürür.

Örneğin:

``` python
precision_score(
    y_true,
    y_pred,
    average=None
)
```

sonucu yaklaşık:

``` text
[Jedi_precision, Sith_precision]
```

gibi bir array olabilir.

------------------------------------------------------------------------

## `average="micro"`

Bütün sınıfların TP, FP ve FN değerlerini global olarak toplar ve sonra
precision hesaplar.

Çok sınıflı durumda:

\[ P\_{micro} = `\frac{
\sum TP
}`{=tex} { `\sum `{=tex}TP+`\sum `{=tex}FP } \]

şeklinde düşünülebilir.

------------------------------------------------------------------------

## `average="macro"`

Her sınıfın precision'ını ayrı hesaplar ve eşit ağırlıklı ortalamasını
alır.

\[ P\_{macro} = `\frac{
P_1+P_2+\cdots+P_K
}`{=tex} {K} \]

Burada sınıfların sample sayıları önemsenmez.

------------------------------------------------------------------------

## `average="weighted"`

Her sınıfın precision'ını support ile ağırlıklandırır.

\[ P\_{weighted} = `\frac{
\sum_i support_i P_i
}`{=tex} { `\sum`{=tex}\_i support_i } \]

Bu, senin mevcut kodunda kullandığın yöntemdir.

------------------------------------------------------------------------

## `average="samples"`

Özellikle multilabel problemlerinde kullanılır.

Her sample için label bazlı metric hesaplanır ve sample'lar üzerinden
ortalanır.

Senin:

``` text
Jedi / Sith
```

binary classification problemin için genellikle gerekli değildir.

------------------------------------------------------------------------

## `sample_weight=None`

Her sample'a ağırlık vermek için kullanılır.

Varsayılan:

``` python
sample_weight=None
```

dir.

Örneğin bazı sample'ların iki kat önemli olduğunu düşünüyorsan:

``` python
sample_weight = [1, 1, 2, 1, 2]
```

gibi ağırlıklar kullanılabilir.

------------------------------------------------------------------------

## `zero_division="warn"`

Precision hesaplanırken:

``` text
TP + FP = 0
```

olursa sıfıra bölme problemi ortaya çıkabilir.

Varsayılan:

``` python
zero_division="warn"
```

dur.

Diğer seçenekler:

``` text
"warn"
0
1
np.nan
```

şeklinde olabilir.

Örneğin:

``` python
zero_division=0
```

ile undefined durumda precision'ın `0` kabul edilmesini seçebilirsin.

`"warn"` kullanıldığında sklearn uyarı vererek uygun davranışı uygular.

# 24. Soru 5 --- F1 zaten harmonik ortalama değil mi? `average` neden var?

**Soru:** `f1_score()` zaten tanım gereği harmonik ortalama ile
hesaplanmak zorunda değil mi? O halde `average` neden var?

Burada çok önemli bir ayrım var.

F1'in tanımı:

\[ F1 = `\frac{
2PR
}`{=tex} { P+R } \]

Evet.

Ama soru şu:

> **Hangi precision ve hangi recall?**

Tek sınıflı/binary-positive-class durumunda:

``` text
Jedi precision
Jedi recall
```

alınabilir.

Ama iki sınıf olduğunda:

``` text
Jedi:
    precision
    recall
    F1

Sith:
    precision
    recall
    F1
```

olur.

Dolayısıyla tek bir F1 üretmek istiyorsak:

> Sınıfların F1 değerlerini nasıl birleştireceğiz?

sorusunu cevaplamamız gerekir.

İşte `average` bunun içindir.

# 25. Çok önemli: `average` F1'in harmonik ortalamasını değiştirmiyor

Örneğin Jedi için:

\[ F1\_{Jedi} = `\frac{
2P_{Jedi}R_{Jedi}
}`{=tex} { P\_{Jedi}+R\_{Jedi} } \]

Sith için:

\[ F1\_{Sith} = `\frac{
2P_{Sith}R_{Sith}
}`{=tex} { P\_{Sith}+R\_{Sith} } \]

Bunlar iki ayrı F1 değeridir.

Sonra `average` ile bunları nasıl birleştireceğini seçersin.

------------------------------------------------------------------------

# 26. Örneğin `average="macro"`

Örneğin:

``` text

F1 Sith = 0.70
```

ise:

\[ F1\_{macro} = `\frac{
0.90+0.70
}`{=tex} {2} \]

olur.

Her sınıfa eşit önem verir.

# 27. `average="weighted"`

Support:

``` text
Jedi = 80
Sith = 20
```

olsun.

O zaman:

\[ F1\_{weighted} = `\frac{
80F1_{Jedi}+20F1_{Sith}
}`{=tex} {100} \]

olur.

Dolayısıyla:

``` text
F1 hesabı
   │
   ├── sınıf içindeki P + R
   │       │
   │       ▼
   │      F1
   │
   └── sınıflar arası birleştirme
           │
           ▼
        average
```

şeklinde düşünmelisin.

# 28. F1'in "harmonik ortalama" olması ile `average` aynı seviyede değildir

Bu ayrım çok önemlidir.

``` text

        │
        ▼

        │
        ▼

```

`average` ise:


belirler.

Yani:

# 68. `KNeighborsClassifier` önemli parametreleri

Temel parametreler:

``` python
KNeighborsClassifier(
    n_neighbors=5,
    weights="uniform",
    algorithm="auto",
    leaf_size=30,
    p=2,
    metric="minkowski",
    metric_params=None,
    n_jobs=None,
)
```

Sürümüne göre ek seçenekler bulunabilir.

------------------------------------------------------------------------

## `n_neighbors=5`

Default:

``` python
5
```

Bakılacak komşu sayısıdır.

Sen bunu:

``` python
n_neighbors=k
```

ile değiştiriyorsun.

------------------------------------------------------------------------

## `weights="uniform"`

Default:

``` python
"uniform"
```

Bütün komşulara eşit ağırlık verir.

Örneğin:

``` text
Komşu 1 → Jedi
Komşu 2 → Jedi
Komşu 3 → Sith
```

ise üçü de eşit oy verir.

------------------------------------------------------------------------

## `weights="distance"`

Yakın komşulara daha fazla ağırlık verir.

Örneğin:

``` text
Çok yakın Jedi   → güçlü oy
Uzak Sith        → daha zayıf oy
```

gibi.

Bu bazen performansı artırabilir.

------------------------------------------------------------------------

## `algorithm="auto"`

Default:

``` python
"auto"
```

Veriye göre uygun nearest-neighbor search algoritmasını seçmeye çalışır.

Alternatifler:

``` text
"ball_tree"
"kd_tree"
"brute"
"auto"
```

------------------------------------------------------------------------

## `leaf_size=30`

Default:

``` python
30
```

Ball Tree veya KD Tree gibi yapılarda kullanılan leaf size
parametresidir.

Temel olarak arama yapısının performansını etkiler.

------------------------------------------------------------------------

## `p=2`

Minkowski metric için power parametresidir.

`p=2`:

\[ d(x,z) = `\sqrt{
\sum_i(x_i-z_i)^2
}`{=tex} \]

yani Euclidean distance'a karşılık gelir.

`p=1` ise Manhattan distance'a karşılık gelir.

------------------------------------------------------------------------

## `metric="minkowski"`

Default:

``` python
"minkowski"
```

Distance metric'i belirler.

`p=2` ile birlikte Euclidean distance elde edilir.

------------------------------------------------------------------------

## `metric_params=None`

Metric'e özel ek parametreleri vermek için kullanılır.

Default:

``` python
None
```

------------------------------------------------------------------------

## `n_jobs=None`

Parallel computation için kullanılır.

``` python
n_jobs=-1
```

ile mümkün olan CPU çekirdeklerinin kullanılması istenebilir.

# 77. Savunmada "KNN nasıl çalışıyor?" sorusuna kısa cevap

> KNN, yeni bir sample'ın feature vektörünü training sample'larının
> feature vektörleriyle karşılaştırır. Distance metric kullanarak en
> yakın `k` sample'ı bulur ve bunların sınıflarına göre majority vote
> ile tahmin yapar. Bu nedenle KNN distance-based bir supervised
> classification algoritmasıdır. Feature ölçekleri distance hesabını
> etkilediği için StandardScaler kullandım.

------------------------------------------------------------------------

# 78. Savunmada "Neden StandardScaler?" sorusuna kısa cevap

> Çünkü KNN Euclidean/Minkowski distance kullandığı için feature'ların
> farklı ölçeklerde olması büyük ölçekli feature'ların distance üzerinde
> baskın olmasına neden olabilir. StandardScaler ile feature'ları
> karşılaştırılabilir ölçeğe getiriyorum.

------------------------------------------------------------------------

# 79. Savunmada "Neden farklı k değerleri denedin?" sorusuna kısa cevap

> `k` KNN'in hyperparameter'ıdır. Küçük `k` daha lokal ve noise'a
> duyarlı kararlar verirken çok büyük `k` fazla genelleme yapabilir. Bu
> nedenle farklı `k` değerlerini Validation üzerinde deneyip F1-score'u
> karşılaştırdım.

------------------------------------------------------------------------

# 80. Savunmada "Neden precision grafiği?" sorusuna kısa cevap

> Subject özellikle precision'ın `k` değerine göre nasıl değiştiğini
> göstermemi istiyor. Bu nedenle x eksenine `k`, y eksenine Validation
> precision koydum. Ayrıca subject'in minimum performans kriteri F1
> olduğu için model seçiminde F1'i de hesapladım.

------------------------------------------------------------------------

# 81. Savunmada "Neden weighted?" sorusuna kısa cevap

> Problem iki sınıflı olsa da tek bir positive class seçmek yerine hem
> Jedi hem Sith precision'ını dikkate almak için `average="weighted"`
> kullandım. Böylece her sınıfın precision'ı kendi sample sayısı ile
> ağırlıklandırılıyor.

------------------------------------------------------------------------

# 82. Savunmada "F1 neden weighted?" sorusuna kısa cevap

> F1 her sınıf için precision ve recall'un harmonik ortalamasıdır. İki
> sınıf olduğunda Jedi ve Sith için ayrı F1 değerleri oluşur.
> `average="weighted"` bu sınıf bazlı F1 değerlerini support sayılarına
> göre birleştirerek tek bir genel F1 değeri üretir.

------------------------------------------------------------------------

# 83. Savunmada "k=11 neden seçildi?" sorusuna kısa cevap

> Denediğim `k=1..29` aralığında ilk kez `k=11` için Validation weighted
> F1 değeri `1.0` oldu. Daha sonraki bazı k değerleri de `1.0` verdiği
> için `>` karşılaştırması ilk en iyi değeri korudu ve `k=11` seçildi.

# 87. Önerilen temiz kod iskeleti

``` python
import sys
from pathlib import Path

import pandas as pd
import matplotlib.pyplot as plt
import seaborn as sns

from matplotlib.ticker import PercentFormatter
from sklearn.neighbors import KNeighborsClassifier
from sklearn.metrics import f1_score, precision_score
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline


def load_csv(path: Path) -> pd.DataFrame | None:
    try:
        df = pd.read_csv(path)
        print(f"Loading dataset of dimensions: {df.shape}")
        return df
    except Exception as e:
        print(f"Error loading CSV: {e}")
        return None


def main():

    if len(sys.argv) != 3:
        print(
            "Usage: "
            "python KNN.py Train_knight.csv Test_knight.csv"
        )
        return

    output_dir = Path(__file__).resolve().parent

    train_path = output_dir.parent / sys.argv[1]
    test_path = output_dir.parent / sys.argv[2]

    train_data = load_csv(train_path)
    test_data = load_csv(test_path)

    if train_data is None or test_data is None:
        print("Aborting...")
        return

    training_path = output_dir.parent / "Training_knight.csv"
    validation_path = output_dir.parent / "Validation_knight.csv"

    training_data = load_csv(training_path)
    validation_data = load_csv(validation_path)

    if training_data is None or validation_data is None:
        print("Aborting...")
        return

    X_train = training_data.drop(columns=["knight"])
    y_train = training_data["knight"]

    X_validation = validation_data.drop(columns=["knight"])
    y_validation = validation_data["knight"]

    X_test = test_data.drop(
        columns=["knight"],
        errors="ignore"
    )

    results = []

    best_KNN_f1 = -1.0
    best_f1_k = -1

    for k in range(1, 30):

        model = Pipeline([
            ("scaler", StandardScaler()),
            ("knn", KNeighborsClassifier(
                n_neighbors=k
            ))
        ])

        model.fit(X_train, y_train)

        validation_pred = model.predict(
            X_validation
        )

        precision = precision_score(
            y_validation,
            validation_pred,
            average="weighted"
        )

        f1 = f1_score(
            y_validation,
            validation_pred,
            average="weighted"
        )

        if f1 > best_KNN_f1:
            best_KNN_f1 = f1
            best_f1_k = k

        results.append({
            "k": k,
            "precision": precision,
            "f1": f1,
        })

    results_df = pd.DataFrame(results)

    print("\nValidation results:")
    print("--------------------")
    print(
        results_df.to_string(
            index=False,
            header=["k", "Precision", "F1 Score"]
        )
    )

    print(
        f"\nBest KNN model: "
        f"k={best_f1_k}, "
        f"F1 Score={best_KNN_f1:.4f}"
    )

    final_model = Pipeline([
        ("scaler", StandardScaler()),
        ("knn", KNeighborsClassifier(
            n_neighbors=best_f1_k
        ))
    ])

    final_model.fit(X_train, y_train)

    test_predictions = final_model.predict(X_test)

    with open(
        output_dir / "KNN.txt",
        "w",
        encoding="utf-8"
    ) as file:
        for prediction in test_predictions:
            file.write(f"{prediction}\n")

    plt.figure(figsize=(10, 8))

    sns.lineplot(
        data=results_df,
        x="k",
        y="precision",
        marker="o"
    )

    plt.title("KNN: k-values vs Precision")
    plt.xlabel("k values")
    plt.ylabel("Precision (%)")

    plt.gca().yaxis.set_major_formatter(
        PercentFormatter(1.0)
    )

    plt.grid(True, alpha=0.3)

    plt.savefig(
        output_dir / "knn_precision_plot.png",
        bbox_inches="tight",
        dpi=200
    )

    plt.show()


if __name__ == "__main__":
    main()
```

# 90. Ek Soru 1 — `Pipeline(...)` nedir ve neden Ex05'te kullandık?

**Soru:**
> `Pipeline([("scaler", StandardScaler()), ("knn", KNeighborsClassifier(n_neighbors=k))])` yapısını başka bir `.md` dosyasında önerildiği için kullandım. Normalde bu fonksiyonu ve kullanımı bilmiyorum. Bana `Pipeline` yapısını, fonksiyonu, parametreleri, default değerleri ve dönüş değerini detaylı ve örnekli anlatır mısın?

## 90.1 Önce en basit fikir

`Pipeline`, birkaç sklearn işlemini **tek bir model gibi arka arkaya bağlamamızı** sağlayan bir yapıdır.

Ex05'te bizim istediğimiz işlem sırası:

```text
Ham X
 │
 ▼
StandardScaler
 │
 ▼
Ölçeklenmiş X
 │
 ▼
KNN
 │
 ▼
Tahmin
```

Bunu Pipeline olmadan da yazabiliriz:

```python
scaler = StandardScaler()

X_train_scaled = scaler.fit_transform(X_train)
X_validation_scaled = scaler.transform(X_validation)

knn = KNeighborsClassifier(n_neighbors=5)
knn.fit(X_train_scaled, y_train)

pred = knn.predict(X_validation_scaled)
```

Yani Pipeline yeni bir ML algoritması değildir. **Birden fazla estimator/transformer'ın çalışma sırasını paketleyen bir sklearn nesnesidir.**

```python
model = Pipeline([
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(n_neighbors=5))
])
```

Artık dışarıdan bunu tek bir estimator gibi kullanabiliriz:

```python
model.fit(X_train, y_train)
pred = model.predict(X_validation)
```

Pipeline'ın temel amacı, ardışık preprocessing ve model adımlarını birlikte yönetmektir. sklearn dokümantasyonuna göre ara adımlar transformer olmalı (`fit` + `transform`), son adım ise estimator olmalıdır; son estimator'ın `transform` sağlaması gerekmez. Pipeline ayrıca adımların parametrelerini birlikte ayarlamayı ve cross-validation içinde bu adımları birlikte çalıştırmayı kolaylaştırır. citeturn0search6turn0search4

## 90.2 `Pipeline` fonksiyon değil, class'tır

Şu kullanım:

```python
Pipeline([...])
```

teknik olarak bir fonksiyon çağırmaktan ziyade `sklearn.pipeline.Pipeline` sınıfından bir **Pipeline nesnesi oluşturur**.

Import:

```python
from sklearn.pipeline import Pipeline
```

Sonra:

```python
model = Pipeline([...])
```

`model` artık bir Pipeline nesnesidir.

## 90.3 `steps` parametresi nedir?

Temel parametre:

```python
Pipeline(steps, ...)
```

`steps`, sıralı `(isim, estimator)` çiftlerinden oluşan listedir.

Örneğin:

```python
Pipeline([
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(n_neighbors=5))
])
```

Burada:

| Sıra | İsim | Nesne | Görevi |
|---|---|---|---|
| 1 | `scaler` | `StandardScaler()` | Feature'ları ölçekler |
| 2 | `knn` | `KNeighborsClassifier(...)` | Sınıflandırma yapar |

Buradaki isimleri biz seçiyoruz. Örneğin şunu da yazabilirdik:

```python
Pipeline([
    ("olceklendirici", StandardScaler()),
    ("siniflandirici", KNeighborsClassifier(n_neighbors=5))
])
```

Ama sklearn dünyasında kısa ve açıklayıcı isimler kullanmak daha pratiktir.

## 90.4 Neden son adım KNN olabilir ama `StandardScaler` olamaz?

Pipeline'ın ara adımları veriyi bir sonraki adıma aktarabilmelidir. Bu nedenle ara adımın `fit()` ve `transform()` metodları olması gerekir.

`StandardScaler` bunu yapabilir:

```text
fit()
transform()
fit_transform()
```

KNN ise bizim Pipeline'ımızdaki **son estimator** olarak görev yapar:

```text
fit()
predict()
```

Dolayısıyla:

```python
Pipeline([
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(n_neighbors=5))
])
```

mantıklıdır.

## 90.5 Pipeline'ın temel parametreleri ve default değerleri

Güncel sklearn dokümantasyonundaki imza kabaca şöyledir:

```python
Pipeline(steps, *, transform_input=None, memory=None, verbose=False)
```

| Parametre | Default | Anlamı |
|---|---|---|
| `steps` | zorunlu | Pipeline'ın sıralı adımları |
| `transform_input` | `None` | Metadata routing kullanıldığında bazı `fit` girdilerinin pipeline boyunca dönüştürülmesini sağlar |
| `memory` | `None` | Ara transformer'ların sonuçlarını cache etmek için kullanılır |
| `verbose` | `False` | `True` ise fit sırasında adımların sürelerini yazdırır |

`transform_input` modern sklearn'de bulunan ileri seviye bir özelliktir ve Ex05 için gerekli değildir. `memory` de bu küçük veri setinde gerekli değildir. `verbose` ise yalnızca işlem sürelerini görmek istersen kullanılabilir. citeturn0search4

### `steps` örneği

```python
steps = [
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(n_neighbors=5))
]

model = Pipeline(steps)
```

### `verbose=True` örneği

```python
model = Pipeline(
    [
        ("scaler", StandardScaler()),
        ("knn", KNeighborsClassifier(n_neighbors=5))
    ],
    verbose=True
)
```

Böylece fit sırasında adımların ne kadar sürdüğünü görebilirsin.

## 90.6 Pipeline'ın dönüş değeri nedir?

```python
model = Pipeline([...])
```

ifadesi sana bir **Pipeline nesnesi** döndürür.

Henüz model eğitilmiş değildir.

```python
model = Pipeline([
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(n_neighbors=5))
])
```

Bu noktada:

```text
Pipeline nesnesi var
        │
        └── fakat henüz fit edilmedi
```

Sonra:

```python
result = model.fit(X_train, y_train)
```

`fit()` işlemi Pipeline'ın kendisini döndürür (`self`), yani pratikte `result` yine fitted Pipeline nesnesidir.

Ardından:

```python
pred = model.predict(X_validation)
```

`predict()` ise son estimator'ın tahminlerini döndürür.

Bizim örneğimizde bu:

```text
numpy array
↓
her validation sample için bir sınıf tahmini
```

olur.

## 90.7 `fit()` Pipeline içinde tam olarak ne yapıyor?

Şunu yazdığında:

```python
model.fit(X_train, y_train)
```

Pipeline kabaca şu işlemleri yapar:

```text
X_train
   │
   ▼
StandardScaler.fit(X_train)
   │
   ▼
StandardScaler.transform(X_train)
   │
   ▼
ölçeklenmiş X_train
   │
   ▼
KNN.fit(ölçeklenmiş X_train, y_train)
```

Önemli nokta:

> `StandardScaler` eğitim verisinden mean ve standard deviation gibi değerleri öğrenir; KNN de ölçeklenmiş training noktalarını kullanacak şekilde fit edilir.

## 90.8 `predict()` Pipeline içinde ne yapıyor?

Şunu yazdığında:

```python
pred = model.predict(X_validation)
```

kabaca:

```text
X_validation
      │
      ▼
StandardScaler.transform(X_validation)
      │
      ▼
ölçeklenmiş validation noktaları
      │
      ▼
KNN.predict(...)
      │
      ▼
validation predictions
```

Burada özellikle dikkat et:

```python
StandardScaler.fit_transform(X_train)
```

ama validation için:

```python
StandardScaler.transform(X_validation)
```

kullanılır.

Validation verisi scaler'ın mean/std değerlerini öğrenmek için kullanılmaz.

Pipeline bunu doğru sırayla otomatik olarak yönetir.

## 90.9 Pipeline'ın Ex05 açısından en büyük avantajı: leakage riskini azaltması

Pipeline kullanmanın çok önemli bir avantajı da preprocessing işleminin model eğitim sürecine düzgün bağlanmasıdır.

Örneğin yanlış yaklaşım şu olabilir:

```python
scaler = StandardScaler()

X_all_scaled = scaler.fit_transform(X)
```

Sonra `X_all_scaled` üzerinden training/validation ayırmak.

Burada validation bilgisinin scaler'ın hesapladığı istatistiklere karışma ihtimali vardır.

Daha doğru yaklaşım:

```python
model = Pipeline([
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(n_neighbors=5))
])

model.fit(X_train, y_train)
pred = model.predict(X_validation)
```

Böylece scaler yalnızca training kısmında fit edilir; validation yalnızca transform edilir.

Bu özellik Pipeline'ı özellikle cross-validation ve hyperparameter tuning sırasında çok değerli hale getirir. citeturn0search6

## 90.10 Pipeline ile parametre değiştirme: `__` sözdizimi

Pipeline'ın çok önemli bir başka özelliği vardır.

Adımların parametrelerine şu şekilde erişebiliriz:

```text
adım_adı__parametre_adı
```

Örneğin:

```python
model.set_params(knn__n_neighbors=11)
```

Buradaki:

```text
knn
```

Pipeline step adı,

```text
n_neighbors
```

ise KNN parametresidir.

Dolayısıyla:

```python
knn__n_neighbors=11
```

şu anlama gelir:

> `knn` isimli step'in `n_neighbors` parametresini 11 yap.

Bu özellik `GridSearchCV` ile özellikle önemlidir:

```python
param_grid = {
    "knn__n_neighbors": [1, 3, 5, 7, 11, 15]
}
```

Böylece scaler + KNN birlikte CV içinde çalıştırılabilir.

# 91. Ek Soru 2 — KNN validation noktasının komşularını nereden buluyor?

**Soru:**
> Fit işleminden sonra validation setindeki yeni bir noktanın `k` tane komşusuna validation setinden değil de training setinden mi bakılıyor? O zaman algoritma nokta bazlı mı; validation setinin bütünü bir anlamda önemli değil, teker teker noktaların ayrı önemi var, doğru mu?

## 91.1 Evet: validation noktası komşularını Training setinden bulur

Bu çok önemli bir KNN noktasıdır.

Örneğin:

```text
TRAINING
A
B
C
D
E
F

VALIDATION
X ← yeni nokta
Y ← yeni nokta
Z ← yeni nokta
```

`X` validation örneğinin tahminini yaparken KNN:

```text
X
│
├── Training A'ya uzaklık
├── Training B'ye uzaklık
├── Training C'ye uzaklık
├── Training D'ye uzaklık
├── Training E'ye uzaklık
└── Training F'ye uzaklık
```

hesaplar.

Sonra en yakın `k` training örneğini seçer.

**Validation'daki Y ve Z noktaları X'in komşusu olarak kullanılmaz.**

## 91.2 Somut örnek

İki feature olduğunu düşünelim:

```text
Training:

A = (1, 1) → Jedi
B = (2, 1) → Jedi
C = (8, 8) → Sith
D = (9, 8) → Sith
```

Validation:

```text
X = (1.5, 1.2)
```

`k=3` olsun.

KNN yaklaşık olarak:

```text
X → A : çok yakın
X → B : çok yakın
X → C : çok uzak
X → D : çok uzak
```

en yakın 3 training noktasını seçer.

```text
A → Jedi
B → Jedi
C → Sith
```

oylama:

```text
Jedi = 2
Sith = 1
```

Sonuç:

```text
X → Jedi
```

## 91.3 Validation'ın tamamı o zaman tamamen gereksiz mi?

Hayır. Burada iki farklı seviyeyi ayırmak gerekiyor.

### Prediction seviyesi

Tek bir validation noktası için:

```text
validation X
      │
      ▼
training noktalarına uzaklık
      │
      ▼
en yakın k
      │
      ▼
oylama
      │
      ▼
prediction
```

Bu anlamda **evet, prediction nokta bazlıdır.**

### Evaluation seviyesi

Fakat sonra bütün validation noktalarının prediction'larını toplarız:

```text
X1 → doğru
X2 → doğru
X3 → yanlış
X4 → doğru
X5 → yanlış
...
```

ve:

```python
precision_score(y_validation, validation_pred)
f1_score(y_validation, validation_pred)
```

hesaplarız.

Yani validation setinin tamamı **KNN'nin tek bir noktayı tahmin etmesi için kullanılmaz**, fakat modelin performansını ölçmek için bütün validation seti kullanılır.

Bu ayrım çok önemlidir:

```text
KNN prediction
→ sample-by-sample

Validation evaluation
→ bütün validation samples birlikte
```

## 91.4 Daha da önemli bir nokta: KNN `fit()` sırasında aslında ne öğreniyor?

Decision Tree'de `fit()` sırasında gerçekten ağaç yapısı öğreniliyordu:

```text
feature seçimi
threshold seçimi
node'lar
branch'ler
leaf'ler
```

KNN'de durum farklıdır.

KNN'nin temel fikri:

> "Ben karmaşık bir karar sınırı öğrenmek yerine training örneklerini saklarım; yeni örnek geldiğinde bunlara olan uzaklıklarına bakarım."

Bu nedenle KNN çoğu zaman **instance-based** veya **lazy learning** olarak anlatılır.

Pipeline kullandığımız için burada yine önemli bir ayrıntı vardır:

```text
StandardScaler
→ training verisinden scaling parametrelerini öğrenir

KNN
→ training noktalarını kullanır
```

Dolayısıyla `fit()` tamamen "hiçbir şey yapmıyor" değildir; ama Decision Tree gibi açık bir karar ağacı yapısı öğrenmez.

## 91.5 Validation noktaları birbirlerinin komşusu olabilir mi?

Normal supervised validation senaryomuzda **hayır**.

Çünkü prediction sırasında KNN'nin referans noktaları training setidir.

Bu nedenle:

```text
TRAINING = referans / memory
VALIDATION = tahmin edilecek yeni örnekler
```

gibi düşünebilirsin.

Validation setini training setine katarsan artık o validation örnekleri de KNN'nin referans noktaları haline gelir. Bu da artık aynı değerlendirme senaryosu olmaz.

## 91.6 KNN'yi çok güzel anlatan bir benzetme

Bir sınıfa yeni öğrenci geldiğini düşün.

Yeni öğrencinin hangi gruba ait olduğunu anlamak istiyorsun.

Eğitimde tanıdığın öğrenciler:

```text
Ali   → Jedi
Ayşe  → Jedi
Can   → Sith
Deniz → Sith
Ece   → Jedi
```

Yeni öğrenci geldi:

```text
Mert → ?
```

Mert'in özellikleri açısından en çok benzeyen 3 öğrenciyi buluyorsun:

```text
Ayşe  → Jedi
Ece   → Jedi
Can   → Sith
```

2'ye 1 olduğu için:

```text
Mert → Jedi
```

Mert'in tahminini yaparken "gelecekte değerlendireceğin diğer yeni öğrenciler" referans alınmıyor.

KNN'nin temel mantığı tam olarak budur.

# 92. Ek Soru 3 — `final_model.fit(X, y)` yapmak mantıklı mı?

**Soru:**
> "`X` ve `y` Ex05'ün geri kalanında kullanılmıyor" kısmını değiştirdim. Artık `final_model.fit(X, y)` kullanıyorum. Ex04'te de böyle yapmıştık. Mantıklı değil mi?

## 92.1 Evet, burada yaptığın değişiklik mantıklı

Senin başlangıçta:

```python
X = train_data.drop(columns=["knight"])
y = train_data["knight"]
```

şeklinde oluşturduğun `X` ve `y`, bütün `Train_knight.csv` içindeki labeled veriyi temsil ediyor.

Sen daha sonra:

```python
X_train
X_validation
```

diye bunu iki parçaya ayırmışsın; fakat Ex05'te zaten DS3'ten gelen:

```text
Training_knight.csv
Validation_knight.csv
```

dosyalarını kullanıyorsun.

Dolayısıyla tuning aşamasında:

```text
Training_knight.csv
        ↓
model.fit()
        ↓
Validation_knight.csv
        ↓
F1 / Precision
        ↓
best k
```

yapıyorsun.

## 92.2 Peki neden final modelde tekrar `X, y` kullanabiliriz?

Çünkü `best_k` artık seçilmiş durumda.

Örneğin:

```text
k=1  → F1=0.926
k=3  → F1=0.975
k=5  → F1=0.988
k=11 → F1=1.000  ← seçildi
```

Artık `k=11` için:

```text
"Hangi k daha iyi?"
```

sorusunu sormuyoruz.

Bu soru zaten cevaplandı.

Şimdi:

> "Seçtiğim `k=11` modeli elimdeki bütün labeled training bilgisini kullanarak son kez eğiteyim."

diyebiliriz.

Bu nedenle:

```python
final_model.fit(X, y)
```

mantıklıdır.

Buradaki `X, y`:

```text
Train_knight.csv'nin tamamı
```

ise, model artık:

```text
Training_knight.csv
        +
Validation_knight.csv
        ↓
hepsini kullanarak
        ↓
final model
```

haline gelir.

## 92.3 Bu neden Ex04'teki yaklaşıma benziyor?

Ex04'te de aynı mantık vardı:

```text
1. Training / Validation ile max_depth seç
2. best_depth'i bul
3. final Decision Tree oluştur
4. bütün X, y ile final fit
5. Test üzerinde predict
```

KNN'de de:

```text
1. Training / Validation ile best_k seç
2. best_k'i bul
3. final Pipeline oluştur
4. bütün X, y ile final fit
5. Test üzerinde predict
```

oluyor.

Dolayısıyla Ex04'te yaptığımız yaklaşım ile Ex05'teki yaklaşımın bu kısmı aynıdır.

## 92.4 Çok önemli bir nüans

Burada `X, y` **Test_knight.csv değildir**.

Doğru ayrım:

```text
Train_knight.csv
│
├── X = feature'lar
└── y = knight label'ları

Test_knight.csv
│
└── X_test = feature'lar
```

Yani:

```python
final_model.fit(X, y)
```

ile:

```python
final_model.predict(X_test)
```

yapmak doğrudur.

Test verisinin etiketleri olmadığı için test setini `fit()` içine vermiyoruz.

## 92.5 Bu durumda Validation'ın bilgisi tamamen boşa mı gitti?

Hayır.

Validation'ın görevi:

```text
best k'yi seçmek
```

oldu.

Örneğin:

```text
Validation sonucu

k=5  → 0.9875
k=7  → 0.9875
k=11 → 1.0000
```

Bu bilgi sayesinde:

```python
best_f1_k = 11
```

seçtik.

Sonra bütün labeled veriyi kullanarak:

```python
final_model = Pipeline([
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(n_neighbors=11))
])

final_model.fit(X, y)
```

yapıyoruz.

Bu nedenle Validation'ın görevi **modelin son halinde mutlaka içinde bulunmak değil**, model seçiminde yol göstermektir.

# 93. Ek Soru 4 — Grafik için `Precision (%)` mı, `accuracy` mi?

**Soru:**
> "Grafik için şimdi sözlü ifadeyi (`precision %`) yoksa görseli mi seçmeliyim (`accuracy`)?"

## 93.1 Burada kesinlikle `Precision` demelisin

Senin kodunda hesaplanan değer:

```python
precision = precision_score(
    y_validation,
    validation_pred,
    average="weighted"
)
```

Dolayısıyla grafik gerçekten **precision** grafiğidir.

Şu an kodundaki:

```python
plt.ylabel("accuracy")
```

yanlıştır.

Çünkü:

```text
accuracy ≠ precision
```

## 93.2 Subject açısından hangisini tercih etmelisin?

Subject metninde açıkça:

```text
precision %
```

deniyor.

Dolayısıyla sözlü talep ile grafikteki eksen adlandırması çelişiyor gibi görünüyorsa, **ölçtüğün gerçek metriği doğru isimlendirmek** en güvenli yaklaşımdır.

Sen precision hesaplıyorsun.

O halde:

```python
plt.ylabel("Precision (%)")
```

kullan.

Daha da önemlisi, grafiğin y ekseninde değerleri gerçekten yüzde olarak göstermek istiyorsan `0.98` yerine `98%` gösterebilirsin.

Örneğin:

```python
import matplotlib.ticker as mtick

plt.gca().yaxis.set_major_formatter(mtick.PercentFormatter(1.0))
```

Böylece:

```text
0.90 → 90%
0.95 → 95%
1.00 → 100%
```

gibi gösterilir.

## 93.3 Peki subject'teki görsel neden `accuracy` yazıyor?

Burada iki şeyi birbirinden ayırmak gerekir:

```text
Subject'in yazılı talebi
→ precision %

Örnek grafiğin eksen etiketi
→ accuracy
```

Senin yaptığın hesap ise:

```text
precision_score(...)
```

olduğu için grafiğe `accuracy` yazarsan grafik ile kodun birbirini yanlış anlatmış olur.

Bu nedenle ben olsam:

```python
plt.title("KNN: k-values vs Precision")
plt.xlabel("k values")
plt.ylabel("Precision (%)")
```

şeklinde yapardım.

## 93.4 "Precision'ın kendisine accuracy denebilir mi?"

Hayır.

Accuracy genel anlamda "model ne kadar doğru?" gibi gündelik bir ifade olarak kullanılabilir; fakat makine öğrenmesinde **Accuracy ayrı ve belirli bir metriktir**.

Accuracy:

$$ Accuracy = \frac{TP + TN}{TP + TN + FP + FN} $$

Precision:

$$ Precision = \frac{TP}{TP + FP} $$

Recall:

$$ Recall = \frac{TP}{TP + FN} $$

F1:

$$ F1 = \frac{2 \times Precision \times Recall}{Precision + Recall} $$

Dolayısıyla:

```text
"modelin başarısı / accuracy anlamında"
```

gibi gündelik bir kullanım yapılabilir; fakat grafik ekseninde ölçülen metriğin adı accuracy ise gerçekten `accuracy_score` hesaplamış olmalısın.

Senin grafiğinde hesaplanan şey precision olduğundan eksen de precision olmalı.

Senin mevcut kodunun son kısmını şöyle yapmanı öneririm:


Burada `marker="o"` zorunlu değildir; sadece `k` değerlerinin tek tek denendiğini görsel olarak daha belirgin hale getirir.

## 93.6 Son karar

Senin durumda:

```text
Kodda hesaplanan metrik
        ↓
precision_score()
        ↓
DataFrame sütunu
        ↓
precision
        ↓
Grafik y değeri
        ↓
precision
        ↓

        ↓

```

olmalı.

**Yani görselde `accuracy` yazıyor diye sen de `accuracy` yazma. Gerçekte hesapladığın metriği yaz.**

# 95. Ex05 için zihinsel model

Ex05'i artık şu zincir halinde düşünmek en doğru yaklaşım olur:

```text
Train_knight.csv
        │
        ▼
Training / Validation
        │
        ├──────────────────────┐
        │                      │
        ▼                      ▼
Training                  Validation
        │                      │
        ▼                      │
StandardScaler               │
        │                      │
        ▼                      │
KNN(k)                        │
        │                      │
        └──────────┐           │
                   ▼           │
             validation point │
                   │           │
                   ▼           │
       Training noktalarına    │
       uzaklık hesapla         │
                   │           │
                   ▼           │
              en yakın k       │
                   │           │
                   ▼           │
             majority vote    │
                   │           │
                   ▼           │
             prediction       │
                   │           │
                   └───────────┘
                           │
                           ▼
                    Precision / F1
                           │
                           ▼
                       best k
                           │
                           ▼
                 Pipeline + best k
                           │
                           ▼
                     fit(X, y)
                           │
                           ▼
                    Test_knight.csv
                           │
                           ▼
                       predict()
                           │
                           ▼
                         KNN.txt
```

Buradaki en kritik fikir şudur:

> **KNN'nin validation prediction'ı validation setinin kendi içindeki komşulara bakarak yapılmaz. Her validation örneği, training setindeki örneklere göre sınıflandırılır. Validation setinin tamamı ise sonrasında modelin precision/F1 performansını ölçmek için kullanılır.**
